Escape Progression and Economy

Evidence Base

Grounding Context

Escape already has the first layer of the roguelite loop: embers, temporary campfire supplies, bargains with next-run curses, daily runs, a run chronicle, relics, rest rooms, and a balance simulator. The problem is therefore not "add progression from zero"; it is to reshape the existing loop so the economy creates hard choices and progression adds durable goals.

The strongest direct economy signal is the mismatch between income and sinks: calculateEmberReward pays from depth, defeated enemies, carried gold, and victory, with a tested victory example totaling 54 embers. Current campfire purchase prices are 4, 6, 8, 10, and 6 embers. Current bargains add 10 or 8 embers immediately and apply a single next-run curse.

The strongest direction-setting signal is already in the repo docs: the first campfire pass explicitly avoided permanent power creep and deferred permanent unlocks, randomized campfire offers, and later balance passes. External grounding points the same way: Vampire Survivors succeeds through content-heavy unlocks and persistent power/loadout goals, while Slay the Spire shows how opt-in challenge ladders can preserve fairness and replay depth.

I1.Ash and Kindling Economy

Confidence 88% Complexity Medium
Description
Split the flat ember wallet into two reward streams: short-lived or aggressively spendable Ash for next-run preparation, and slower Kindling for permanent unlocks. Depth and victory can feed Kindling, while kills, gold, and run performance feed Ash, or the split can start simpler with a percentage conversion from each run.
Axis
Ember faucet and sink economy
Basis
direct: src/game/metaRewards.ts:21-31 combines room, enemy, gold, and victory embers into one total; src/data/campfirePurchases.ts:47-85 prices all current supplies at 4-10 embers; src/meta.ts:11-17 already centralizes persistent meta.
Rationale
The user complaint is specifically about liquid embers making every purchase affordable. A split preserves the rewarding end screen while making only part of the reward immediately spendable, and it creates a natural home for permanent progression without making daily or base runs permanently stronger.
Downsides
Two currency names add UI and teaching cost. If the split is too stingy, early losses may feel unrewarding; if it is too generous, the same inflation returns in two wallets.

I2.Hearthboard Forge

Confidence 86% Complexity High
Description
Add a permanent board that unlocks option breadth rather than passive stats: extra starting-card packages, bargain families, relic families, room modifiers, scouting tools, and campfire offer types. Before a run, the player equips only a limited number of unlocked doctrines or slots, so progress creates identity and choice rather than stacking every advantage.
Axis
Permanent unlock and meta-progression seams
Basis
direct: earlier campfire planning kept permanent upgrades out of the first pass and deferred permanent unlocks; current progression planning preserves that no-power-creep direction; external: Vampire Survivors uses permanent power-up and unlock goals as its long-tail loop.
Rationale
This most directly answers the request for a progression system while respecting the repo's stated no-power-creep direction. The player gets durable goals and new toys, but each run still has a build decision instead of automatic account strength.
Downsides
It is the largest product move in the set. It needs a clear first slice and careful content gating or it becomes a UI shell with too few meaningful unlocks.

I3.Chronicle Unlock Contracts

Confidence 84% Complexity Medium
Description
Use run feats as the achievement layer: first boss reach, first cursed escape, win without purchases, survive multiple traps, defeat a boss after taking Blood Oath, or clear a daily. Each contract unlocks future content pools such as relics, bargain templates, starting-card packs, bosses, room variants, or Hearthboard slots.
Axis
Content and variety unlock surfaces
Basis
direct: src/chronicle.ts:4-23 already stores run id, completion time, seed, daily key, escape flag, depth, defeated enemies, gold, and ember reward; src/chronicle.ts:127-148 updates runs completed, escapes, best depth, best gold, best enemies defeated, and recent entries.
Rationale
Vampire Survivors-style progression feels good because unlocks are goals, not only store purchases. The chronicle already gives Escape a lightweight basis for that: progress can come from how a run was played, including failed runs, instead of simply from accumulating embers.
Downsides
The current chronicle keeps only a compact history. Some unlock conditions may need new counters, and the end screen must make progress visible enough that the system does not feel hidden.

I4.Nightfall Heat Ladder

Confidence 82% Complexity Medium
Description
Add an opt-in challenge ladder from the campfire for normal runs only. Each Nightfall level changes one legible rule: fewer rests, reduced potion room odds, harsher trap density, stronger late encounters, pricier supplies, boss modifiers, or stricter ember conversion. Climbing the ladder unlocks content or Kindling velocity, not unchecked liquid embers.
Axis
Challenge tuning and balance validation
Basis
direct: src/game/balanceSimulator.test.ts:5-30 already asserts baseline and prepared win-rate bands; src/scenes/Campfire.ts:389-394 starts daily runs separately from normal runs; external: Slay the Spire's Ascension model shows that opt-in difficulty can preserve base-run fairness.
Rationale
This answers "not challenging enough" without making the default game hostile for new players. It also gives progression a skill expression outlet: stronger players can choose higher pressure for better unlock progress while daily runs stay comparable.
Downsides
A bad first heat tier can feel like punishment rather than mastery. Each modifier should be visible, isolated, and simulator-checked before stacking levels.

I5.Economy Autopilot

Confidence 80% Complexity Medium
Description
Extend the existing balance simulator so it models the meta loop, not only run win rates. Add scenario profiles for careful player, greedy buyer, bargain taker, cursed run, full-prep run, heat climber, and broadened unlock pool. Track average stored Ash/Kindling, spend rate, bargain uptake, curse survival, boss reach, unlock velocity, and whether stockpiles trend upward unchecked.
Axis
Challenge tuning and balance validation
Basis
direct: src/game/balanceSimulator.ts already simulates runs using room events, enemy spawning, rewards, prep, and battle resolution; src/game/balanceSimulator.test.ts:8-30 asserts expected bands for baseline and prepared runs.
Rationale
The current problem is partly a balancing failure that the existing simulator does not yet measure. Once permanent progression, rotating offers, and challenge tiers arrive, manual feel-testing will be too slow. A meta simulator turns "bargains are dead" into a detectable regression.
Downsides
Simulation can lie if player heuristics are too simple. It should guide thresholds and catch obvious economy drift, not replace manual playtesting.

I6.Campfire Draft Market

Confidence 70% Complexity Medium
Description
Replace the static "all supplies always visible" campfire economy with a small drafted offer set each visit: one stabilizer, one greed play, one odd or risky play, and later one permanent-unlock opportunity. Embers buy scarce timing, not just entries from a solved checklist. As the Hearthboard grows, it expands the market pool rather than making every option always available.
Axis
Ember faucet and sink economy
Basis
direct: src/data/campfirePurchases.ts:47-85 defines a fixed purchase catalog; earlier roadmap notes treated randomized campfire offers as useful once bargains exist and the choice pool grows. The verifier marked this weaker than the top five because unlock offers are not supported yet, but the static-shop pain is directly tied to the user's complaint.
Rationale
Even if the economy is tuned down, a full static shop becomes solved. A draft market restores opportunity cost: the player can have enough embers and still face a hard choice because the right offer may not appear again this run cycle.
Downsides
The current pool is still small, so this should follow or ship alongside a few new purchases, bargains, or unlockable offer types. Too much randomness can also feel unfair if baseline survival depends on a missing stabilizer.

Rejection Summary

1 Oath Contracts Good bargain direction, but persistent debt is under-evidenced compared with simpler curse/content and economy ideas.
2 Forbidden Content Curses Strong as a later Hearthboard or Chronicle variant, but too speculative as a standalone top direction.
3 Stakefire / Ember Escrow Runs Interesting sink, but less grounded than the two-currency economy and heat ladder.
4 Boss Tax / Boss Progression Spine Boss extensibility exists, but this makes bosses carry too much of the whole progression spine too early.
5 League Rulesets Useful later challenge variety, but a broader new design layer than the immediate economy/progression problem needs.
6 Curse Auction Expressive bargain tuning, but current bargain pool is too small for variable severity to be the first move.
7 Burn Rate / Overburn Pricing Addresses stockpiles, but hoard-scaling prices feel punitive and are weaker than structural sink changes.
8 Locked Embers Tempered by Achievements Overlaps with Ash and Kindling plus Chronicle Unlocks while being harder to explain.
